# AI 玩家

- **状态：** 已定稿（第 7 步）
- **对应功能：** 服务端脚本控制的 AI 城，使用与真人相同的建造 / 征兵 / 出兵接口
- **实现顺序：** 第 7 步（见 [路线图](design-roadmap.md)）

AI **不走另一套战斗或建造公式**。难度只来自模板（先升级什么、带多少兵），战斗侧不开后门。

## 范围

| 做 | 不做 |
|----|------|
| 启动时若不足则生成若干 AI 账号 / 角色 / 主城 | 机器学习、独立客户端 |
| Hangfire 周期 tick「替 AI 点按钮」 | 战斗公式作弊 |
| AI 可升级建筑、收取、征兵、打 NPC / 玩家 | 为 AI 单独做一套表结构绕过 Core |

## 身份

占用真实账号表，带标记：

| 字段 | 约定 |
|------|------|
| `sg_account.is_ai` | `true` |
| 用户名 | `ai_001` … `ai_00N`（已存在则跳过） |
| 角色名 | 固定池：黄巾甲、黄巾乙、董卓部、袁术军 等，撞名则加数字 |
| 密码 | 随机，不提供给网页登录流程使用 |

第一版默认生成 **8** 座 AI 城（`WorldMap:AiCityCount`）。建城走与玩家相同的随机空地逻辑（会避开已有城与据点）。

## Tick

Hangfire 周期任务 `AiTick`，默认每 **5** 分钟（`WorldMap:AiTickMinutes`）。对每个 `is_ai` 且已有主城的账号顺序执行，单个 AI 失败不影响其他。

每个 tick 按固定模板（全部走现有应用服务）：

1. **收取** 城外田（`CollectAsync`，四座都收）。
2. **建造：** 若全城队列空闲，按优先级尝试升级一档：主殿 → 民居 → 仓库 → 兵营 → 良田 → 木场 → 箭塔 → 城门。资源或前置不够则跳到下一项。
3. **征兵：** 兵营 ≥ 1 且总兵 < `troopCap / 2` 时，征步兵最多 10 名（资源不够则少征或不征）。
4. **出征：** 驻城步兵 ≥ 20 且行军数未达上限时，找曼哈顿距离 ≤ 40 的目标：优先未战败（或已恢复）的 NPC 据点；没有则找未保护、兵力总数更少的玩家城。出征 20 步兵。

AI 被打、被掠走与玩家相同的第 6 步管线。

## 验收对应

- 新档或空库启动后地图上有 AI 城（不足则补）。
- tick 日志可追到与真人相同的 `BuildingService` / `ArmyService` / `MarchService`。
- 玩家攻打 AI 城走 `targetType = city`。

## 本步不做

强化学习、AI 专用战斗加成、AI 控制的网页会话。
