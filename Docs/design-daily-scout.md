# 每日军务与斥候侦察

- **状态：** 已定稿（第 12 步）
- **对应功能：** 每日固定军务、领取犒赏；派斥候侦察据点 / 玩家城，到点写侦察邮件
- **实现顺序：** 第 12 步（见 [路线图](design-roadmap.md)）

行军距离公式见 [行军战斗](design-march-battle.md)。邮件信封见 [邮件](design-mail.md)。

## 为什么做这两项

第一版 0～11 步已经能建城、升级、收田、出征、市集、联盟。缺的是 **短期目标** 和 **出征前的信息**：

| 候选 | 为什么现在不做 / 做 |
|------|---------------------|
| 每日军务 | **做。** 新玩家不知道下一步点什么；老玩家打完据点就空转。固定五条军务给当天循环。 |
| 斥候侦察 | **做。** 关隘和村落强度差很多，现在只能盲打。侦察走同一套行军到点，不另开战斗公式。 |
| 召回行军 | 第一版明确不做取消/加速；要改 Hangfire 退订与途中折返，放到以后。 |
| 占领据点 | 大地图占格、驻军、被反打，会动世界规则，单独一步。 |
| 武将 / 技能 | 新成长线，体量超过本步。 |
| 玩家挂单市集 | 第 10 步已排除。 |

本步不改战斗公式、不占领、不召回。

## 范围

| 做 | 不做 |
|----|------|
| 每天 UTC 0 点切日的 5 条固定军务 + 全勤犒赏 | 随机任务、周常、成就树 |
| 收取 / 下达升级 / 征兵 / 战胜据点 / 市集兑换自动计数 | 同盟运输、侦察、打玩家计入军务 |
| 领奖入仓，受仓库上限截断 | 邮件附件、过期补领昨天 |
| `POST /api/army/scout` 扣 1 步兵，到点写侦察邮件并返回该兵 | 侦察战斗、侦察市集、侦察自己 |
| 侦察占行军槽，半程时间 | 保护期内禁止侦察（保护只挡进攻） |

## 每日军务

### 日界

`day = UTC 日历日的 00:00:00Z`。`GET` 或首次计数时若当天还没有行，按目录插入。昨天未领的奖励作废，不补发。

### 目录（每天相同）

| type | 名称 | 条件 | required | 奖励粮/木/铁/铜 |
|------|------|------|----------|-----------------|
| `collect` | 开仓收粮 | 一次收取且实际入库 > 0 | 1 | 200 / 0 / 0 / 0 |
| `upgrade` | 营建城池 | 成功下达一次城内 / 城外 / 城墙建造或升级 | 1 | 0 / 200 / 0 / 0 |
| `recruit` | 扩军备战 | 征兵人数累计 | 10 | 0 / 0 / 100 / 0 |
| `raid` | 讨伐据点 | 战胜据点 1 次（常驻或流寇；目标消失 / 战败不计） | 1 | 0 / 0 / 0 / 80 |
| `trade` | 市集贸易 | 成功出发一次市集兑换 | 1 | 150 / 150 / 0 / 0 |
| `bundle` | 今日犒赏 | 其余 5 条均已 **完成**（进度满即可，不必先领奖） | 5 | 400 / 400 / 80 / 40 |

进度 `progress = min(required, progress + delta)`。已领奖后不再加进度。

### 表 `sg_daily_quest`

`id, city_id, day, type, progress, claimed`。唯一 `(city_id, day, type)`。

### HTTP

均需登录且已有城。

#### `GET /api/daily`

```json
{
  "serverTime": "2026-08-20T12:00:00.000Z",
  "day": "2026-08-20T00:00:00.000Z",
  "resources": { "grain": 2000, "wood": 2000, "iron": 2000, "copper": 2000 },
  "resourceCap": 12000,
  "missions": [
    {
      "type": "collect",
      "name": "开仓收粮",
      "detail": "收取一次城外产出",
      "progress": 0,
      "required": 1,
      "claimed": false,
      "reward": { "grain": 200, "wood": 0, "iron": 0, "copper": 0 }
    }
  ]
}
```

`missions` 按目录顺序。`bundle` 的 `progress` 为另外 5 条中进度已满的条数。

#### `POST /api/daily/claim { "missionType": "collect" }`

成功返回与 `GET` 相同结构。未完成 → `40929`。已领取 → `40929`。奖励加入仓库，超出上限的部分消失（与战斗缴获相同）。

## 斥候侦察

### 规则

- 兵营 ≥ 1，城上至少 1 名步兵。
- 目标只能是据点或他人城（含 AI）。市集、自己的城 → `40930`。
- 扣 1 步兵作为斥候；弓骑不派。
- 占用 `MaxMarchesPerCity` 槽位，与进攻行军合计。
- 到达时间：`max(ceil(MinMarchSeconds / 2), floor(distance * SecondsPerTile / 2))`。
- `sg_march.kind`：`attack = 0`（默认，旧行）、`scout = 1`。
- 到点 **不战斗、不掠夺、不触发保护、不给守方 `CityAttacked`**。
- 斥候无论目标是否还在，存活步兵加回出发城（受带兵上限截断）。
- 写一封 `type = scout` 的邮件给出发角色；不写战报。
- 推送仍用 `MarchArrived`（前端刷新军队 / 邮件 / 地图即可）。

### 邮件正文

据点：名称、类型、驻军、目录战利品、常驻/流寇、若有 `expiresAt` 则写剩余寿命。目标已消失则写「目标据点已消失」。

玩家城：城名、驻城兵力（行军在外的不计入）、仓库四资源、城防、是否保护中及 `protectionUntil`。

同盟城允许侦察，只看不打。

### HTTP

#### `POST /api/army/scout { "targetType": "outpost"|"city", "targetId": 1 }`

成功返回 `ArmyOverviewDto`（与出征相同）。`marches[].kind` 为 `scout`。

兵力不足 → `40910`。无兵营 → `40915`。行军已满 → `40917`。目标不存在 → `40400`。不可侦察 → `40930`。

`GET /api/army` 与 `GET /api/world` 的行军项增加 `kind`。旧进攻行军为 `attack`。

## 错误码

| 码 | 含义 |
|----|------|
| `40929` | 军务未完成或已领取 |
| `40930` | 目标不可侦察 |

## 安全

- 军务进度只由服务端在成功指令后累加，客户端不能改进度。
- 领奖与入仓在城行锁内，同一 `(city, day, type)` 不能领两次。
- 侦察邮件只发给出发方，不把对方账号、联盟内部字段写进正文。
- 侦察不绕过「不能打自己」；不能用侦察扣别人的兵。

## 验收

- 升级主殿后 `upgrade` 进度为 1，可领 200 木；再领 → `40929`
- 收取实际入库 > 0 后 `collect` 可领
- 征兵 10 人后 `recruit` 可领
- 战胜测试村后 `raid` 可领；战败不加
- 市集兑换出发后 `trade` 可领（不必等运回）
- 5 条进度满后可领 `bundle`
- 斥候扣 1 步兵，到点邮件含驻军，步兵返回
- 侦察自己的城 / 市集 → `40930`
- 无步兵侦察 → `40910`
